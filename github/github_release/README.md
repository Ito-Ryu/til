# GitHub Release

## 概要

GitHub リリースは、リリースノートやバイナリファイルへのリンクを含め、ソフトウェアのイテレーションをパッケージ化してより多くのユーザーに提供するための仕組みです。GitHub 上でのソフトウェア開発ライフサイクルにおいて重要な部分を担っている。

## リリースとは？

リリースは、パッケージ化して他のユーザーがダウンロードして使用できるようにする、デプロイ可能なソフトウェアのイテレーションのこと。
リポジトリの履歴の特定の時点を示す Git タグに基づいている。
タグの作成日とリリース日は異なる場合があることに注意する。

## リリースノート

リリースノートはいくつかの方法で作成できる：
*   **手動**: リリースを管理する際に、直接リリースノートを記述する
*   **自動生成**: GitHub はデフォルトのテンプレートからリリースノートを自動生成できる
*   **カスタムテンプレート**: メッセージの一貫性を保つために、独自のリリースノートテンプレートをカスタマイズできる

## プレリリース

GitHub では、リリースを「プレリリース」としてマークすることができる。
これは、安定版リリースの前に、不安定なビルドやベータ版を配布してフィードバックを収集するのに役立つ。
プレリリースは通常、リリースページで「Pre-release」バッジで示される。

## 最新リリース (Latest Release)

GitHub は、最も新しい安定版リリースを自動的に「Latest Release（最新リリース）」として指定する。
これにより、ユーザーは推奨されるバージョンのソフトウェアをすばやく特定できる。

## その他の重要な詳細

*   **Git タグ**: リリースは基本的に Git タグにリンクされており、リポジトリの履歴内の特定のコミットを正確に示す。
*   **通知**: リポジトリの他の更新について通知を受け取ることなく、新しいリリースが公開されたときにのみ通知を受け取るようにサブスクライブできる。
*   **権限**: 読み取りアクセス権を持つユーザーは誰でも、リリースを表示および比較できる。ただし、リリースを管理（作成、編集、削除）できるのは、リポジトリへの書き込み権限を持つユーザーのみ。
*   **自動ダウンロード**: GitHub は、リリースタグの時点でのリポジトリのコンテンツを含む `.zip` ファイルと `.tar.gz` 圧縮ファイル（tarball）をダウンロードするためのリンクを自動的に提供できる。
*   **Git LFS サポート**: リポジトリの管理者は、各リリース用に GitHub が生成する `.zip` ファイルと tarball に Git Large File Storage (Git LFS) オブジェクトを含めるかどうかを選択できる。
*   **セキュリティアドバイザリ**: リリースでセキュリティの脆弱性が修正されている場合は、リポジトリでセキュリティアドバイザリを公開することをお勧めされる。GitHub はこれらのアドバイザリをレビューし、影響を受けるリポジトリに Dependabot アラートを送信するために使用する場合がある。
*   **Dependents タブ**: 依存関係グラフの「Dependents（依存先）」タブには、自分のコードに依存している他のリポジトリやパッケージが表示され、新しいリリースの潜在的な影響を理解するのに役立つ。
*   **リリース API**: GitHub はリリースおよびリリースアセット用の REST API を提供しており、リリースアセットのダウンロード数などの情報をプログラムで収集できる。

## ストレージと帯域幅のクォータ

*   1つのリリースに最大 **1000個のリリースアセット** を含めることができる。
*   リリースに含まれる個々のファイルは **2 GiB** 未満である必要がある。
*   リリースの合計サイズや帯域幅の使用量に **制限はない**。
